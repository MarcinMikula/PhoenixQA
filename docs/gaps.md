# Gaps — thematic index

Short-form index of every numbered architectural gap identified so far.
Each entry is a 1-2 line summary + status. **Full reasoning, examples, and
resolution details live in `LEARNINGS.md`** — this file is a map, not a
copy. Use it to quickly check "what's still open" without scrolling
through the full chronological journal.

**Not the same as [`docs/research_hypotheses.md`](research_hypotheses.md):**
a gap here is an architectural TODO — something to build or decide. A
research hypothesis is an open empirical question — something to find
out through evidence, often only answerable once the Sprint 7/8
benchmark runner exists. Some gaps (e.g. #9) exist specifically to
produce the tooling a related hypothesis needs to be answered — building
the tool isn't the same as answering the question.

Gaps are numbered in the order they were raised, not by severity or sprint.

## Current Sprint 6 implication

Sprint 6B should not begin by blindly choosing between `NOT_VISIBLE` and
`TIMEOUT_WAITING` as equal top-level failure types. The latest diagnostic
evidence points to a more Playwright-native model:

```text
Selector resolution failure
└── locator never resolved
    └── selector_not_found-style collector / SelectorReplacement

Actionability failure
└── locator resolved, but action could not be performed
    ├── reason: not visible
    ├── reason: not enabled
    ├── reason: not editable
    ├── reason: not stable
    └── reason: pointer events intercepted / overlay
```

This does not necessarily require renaming the existing `FailureType` enum
immediately, but it DOES mean the classifier needs to understand the
structure of Playwright's call log before the next collector/prompt/action
slice is built. Otherwise PhoenixQA risks sending a correct selector into
the selector-healing pipeline simply because the timeout message contains
`waiting for locator(...)`.
